# Tolerance rows for verify-export.py pass E (internal references), ORDER CR-5c3261ee.
#
# Format: `path:line<TAB>reason`. One row per line of the EXPORTED tree whose mention of an
# internal path (`docs/sintergic/`, `.sintergic/`, `.omp/`, `.opencode/`, `promotion-ledger`)
# counts as functional: a path constant, an `include_str!`, a `fs::read*`, a `Path::new`, a
# `join(...)`, a `startswith(...)` prefix or a scanner pattern. Prose in `.md`, comments, Python
# docstrings (the spans `ast` reports, which is also what `scripts/ci/language-check.py` reads as
# prose) and the exclusion/tolerance data files do not need a row.
#
# No wildcards. A row whose line disappears, moves or stops being functional is a stale row and
# fails pass E, so this file cannot silently widen. A functional line without a row fails pass E
# with the number of offending references. Pass E is not skippable.
#
# Every row below names a path that lives only in the main workspace: the exported tree carries
# the reference, never the record. Each reason states what the line does, in one of three kinds:
#   cited    the path is printed or compared; nothing opens it.
#   read     the path is opened at runtime; the record is absent from the export, so the reason
#            says whether the instrument degrades, reports the absence, or aborts.
#   written  a run materialises the internal path inside the tree.
# `docs/acknowledgments/export-limits.md` §2 narrates the promotion-gate, windowed-demo and
# operator-script cases in full.
